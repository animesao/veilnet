# veilnet Development Rules

## Core principle
Действую **строго по `PLAN_DETAILED.mmd`**. Проект ведётся как отдельный инструмент, фазы идут по порядку, без прыжков вперёд.

## Safety
- **VM ONLY**: Вся работа связанная с eBPF/TC/kernel (генерация vmlinux.h, компиляция BPF, загрузка, attach/detach, тесты) выполняется **только в тестовой Linux VM**. На текущем хосте буду делать только каркас, правки файлов, документацию.
- **Тест после каждой фазы**: Фаза считается завершённой только если выполнены все пункты `ACCEPTANCE` и пройдены `TEST`.
- **Меньше риска**: Сначала userspace-каркас + компиляция BPF в изолированной среде. Без LKM.

## Workflow
1. Взять текущую фазу из `PLAN_DETAILED.mmd` со статусом `IN_PROGRESS` или перейти к следующей `TODO` когда предыдущая `DONE`
2. Выполнить `TASKS` по пунктам
3. Пройти `TEST`
4. Проверить `ACCEPTANCE`
5. Обновить статус фазы в плане, зафиксировать краткий отчёт (что сделано/проверено/файлы)
6. Перейти к следующей

## Tech
- Kernel >= 5.8
- TC clsact + eBPF (libbpf)
- Rust (libbpf-rs) + C (clang -target bpf)
- veilnetd + veilctl
- systemd

## Install philosophy
После реализации veilnet ставится как системный инструмент: бинарники в `/usr/local/bin/`, конфиг в `/etc/veilnet/`, юнит в systemd. Работает фоном, управляется через `veilctl`.
